Privacy policy

Your calendar, with explicit approval.

Effective date: 5 November 2026. This policy describes Espejo’s personal Google Calendar integration and this informational website. The operator is Mitch Hankins, reachable at mitchhankins01@gmail.com.

Information accessed

With the owner’s Google authorization, Espejo reads calendar identity, ownership and list information, and event details from configured calendars. Event details can include titles, dates, times, locations, descriptions, reminders and other metadata returned by Google. Espejo also uses relevant messages, email and conversation records already available in the owner’s private system. Automatic image descriptions may be used as evidence and can contain errors.

Purpose and permissions

Data is used to identify potential plans, compare existing events, prepare proposals, and carry out approved calendar changes. The requested Google permissions are calendar.calendarlist.readonly and calendar.events.owned. The latter permission is broader than the application’s actual write behavior: Espejo limits writes to its configured calendar and requires approval of the exact proposal.

Processing and service providers

Relevant calendar event details and source context are sent to the configured AI service, currently OpenAI, to generate and revise proposals. Proposal details are delivered through Telegram to the owner’s private Updates conversation. Google processes calendar reads and writes. The private server’s hosting and backup infrastructure stores the application’s records. These services process data under their applicable terms and privacy policies. This integration is not used to sell personal data, target advertising or train a general-purpose AI model.

Storage and retention

Google OAuth credentials are stored on the private server in a file restricted to the operating account. Private records can include source context, calendar snapshots, model inputs and outputs, proposal revisions, approvals and write receipts. These records and backups support continuity, duplicate prevention and recovery. They do not currently have an automatic deletion period and remain until the operator removes them. Limited file permissions do not constitute a guarantee against unauthorized access.

Control, revocation and deletion

The owner can dismiss or change proposals before accepting them and can disable the integration. Google access can be revoked through Google Account connections. Revocation stops future authorized API access; it does not delete existing calendar events or previously stored records. The operator can remove stored credentials and records, including retained backup copies, separately. Contact the operator for access or deletion requests.

This website

These static pages contain no analytics scripts, forms or application cookies. They do not receive calendar data or OAuth tokens. When hosted on GitHub Pages, GitHub may process visitor IP addresses and request information for hosting and security under its privacy statement.

Changes

This policy will be updated when the integration’s data practices change. The effective date identifies the current version.
